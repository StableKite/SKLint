# SKLint 0.1.50 — rule-semantics requirements

Source feedback: StableKite R19 corpus review dated 2026-09-05.

## Scope accepted for 0.1.50 candidate

### SK901: direct numeric keyword literals

A direct numeric or signed-numeric literal used as the value of a named keyword argument is self-documenting.

PASS:

```python
func(timeout=0.2)
func(retry_count=3)
func(limit=-5)
```

Still analyzed:

```python
func(0.2)
func(BASE_TIMEOUT * 2)
func(timeout=BASE_TIMEOUT * 2)  # the inner 2 is still SK901-owned
```

The exemption applies only to the direct literal, never to the whole keyword-value subtree.

### SK901: assertion/oracle context

Expected numeric literals are not runtime magic values when they occur inside a recognized assertion/oracle expression.

Built-in contexts:

- Python `assert`;
- `unittest`-style `assertXxx(...)` methods;
- canonical `unittest.mock` assertion methods such as `assert_called_once_with(...)`.

Project-specific helpers are configured in `[tool.sklint]` with simple `*` patterns:

```toml
[tool.sklint]
assertion_helpers = [
    "verify",
    "verify_*",
    "assert_*",
]
```

Patterns match both a qualified call name and its final component.

This is not a path-based exemption. These remain SK901-owned outside an oracle context:

```python
sleep(0.2)
range(40)
allocate(4096)
retry(5)
```

### SK506: lifecycle / cleanup exception boundaries

SK506 remains active in ordinary runtime/hot paths, but explicit `try`/`except` is permitted at lifecycle and cleanup boundaries.

Built-in boundary names:

- `close`;
- `shutdown`;
- `cleanup`;
- `teardown`;
- `rollback`;
- `release`;
- `__exit__`;
- `__aexit__`.

Additional project-specific names use simple `*` patterns:

```toml
[tool.sklint]
exception_boundary_functions = [
    "_rollback_*",
    "probe_*",
]
```

Private helpers inherit boundary semantics only when every observed caller is already a recognized boundary. If a private helper is shared with an ordinary runtime path, SK506 must remain active in that helper.

SK510 is unchanged: `contextlib.suppress(...)` stays forbidden in strict mode even inside a lifecycle boundary.


### Formatter safety: SK504 `sys.platform` binding rewrite

`sklint format` must never remove `from sys import platform` while leaving a semantic reference to the imported `platform` binding behind.

The 0.1.50 candidate uses a fail-closed safe-fix policy:

- a simple file whose only unqualified references are supported `if platform ...` / `elif platform ...` guards may be rewritten to `import sys` + `sys.platform`;
- if the same binding is referenced in a decorator/decorator argument, function default or kwdefault, annotation/type expression, class base/keyword, comprehension, lambda, match guard, module-level expression, nested/shadowed scope, or another unsupported location, SK504 remains a diagnostic but no safe whole-file fix is attached;
- formatter therefore leaves the original binding intact instead of creating a mixed state.

Regression case that must remain executable after formatting:

```python
from sys import platform

@marker(platform == "win32")
def f() -> bool:
    if platform == "win32":
        a()
        b()
    else:
        c()
        d()
    return True
```

Accepted formatter outcomes are only:

1. keep `from sys import platform` and all references unchanged; or
2. rewrite every semantic reference consistently to `sys.platform`.

A mixed state is a correctness failure. The current candidate intentionally chooses outcome 1 whenever complete binding-aware rewrite cannot be proven safe.

### SK608: sibling-order traversal determinism

SK608 evaluation for a nested owner must depend only on the current lexical ancestry, not on a previously visited top-level sibling. In particular, a method directly inside a top-level class must produce the same SK608 result whether the class is first in the module or preceded by a constant, class, sync/async/decorated function, or other independent top-level definition.

The implementation must stop at the first relevant less-indented lexical owner instead of scanning past the containing class into an unrelated earlier top-level function.

### SK619: project-aware duplicate emission

Project-aware dataclass/DataDict resolution must not load the source file currently being analyzed a second time through a package re-export or self-reference chain. Current-module classes must appear once in the semantic model.

As a narrow safety net, exact duplicate SK619 diagnostics are deduplicated only when the full diagnostic identity is equal, including location, message, and fix payload. Distinct SK619 diagnostics and other rule families must not be removed.

Acceptance:

- the same `C.m` SK608 repro yields the same result across class-first, constant/class/function-before-class, async/decorated-function, class->function->class, and function->function->class arrangements;
- the StableKite wrong-order project-aware reproduction emits exactly one SK619 per semantic violation;
- after correcting the Attributes order, SK619 is zero for those classes;
- unrelated SKD602/SKD603/SK619 diagnostics remain unchanged when their location/fix/meaning differ.

### SK507: module `__getattr__` protocol semantics

A module-level function named exactly `__getattr__` is a Python language protocol hook. It may explicitly raise `AttributeError(...)` when a dynamic module attribute does not exist. The exemption is intentionally narrow: it does not apply to methods named `__getattr__`, ordinary functions, or other exception types such as `RuntimeError`.

### SK505: eager vs deferred definition-order semantics

Top-level definition order is evaluated by execution phase rather than textual occurrence alone. A global-name lookup in a function, method, async-function, or stored lambda body is deferred until invocation and does not by itself require the referenced module definition to appear earlier. Eager contexts remain checked, including module/class executable expressions, function defaults/kwdefaults, decorators/decorator arguments, and class bases/keywords.

Acceptance examples:

```python
class A:
    def make(self) -> "B":
        return B()  # deferred: PASS

class B:
    pass
```

```python
INSTANCE = B()  # eager: SK505

class B:
    pass
```

## Explicitly deferred

The local named aggregate / data-constructor issue is not generalized in this candidate. In particular, there is no `CamelCase(...) => allow numeric literals` heuristic. The remaining StableKite SK901 corpus must be reclassified after Issues 1 and 2 are measured.

## StableKite acceptance matrix

The validation chat must rerun at least:

```text
sklint check sk tests
ruff check sk tests
sklint format --check sk tests
python -m compileall sk tests scripts tools
```

Required semantic checks:

- production `sk/` remains SK901-clean;
- `timeout=0.2` no longer requires a dummy variable;
- positional `func(0.2)` remains analyzed;
- `timeout=BASE_TIMEOUT * 2` retains analysis of the inner `2`;
- configured assertion helpers accept direct expected literals and oracle-only arithmetic/containers;
- oracle context stops at nested ordinary runtime calls, whose arguments restore normal SK901 call semantics;
- assertion-method recognition is based on the terminal callable name, so subscript/call/attribute receivers do not change oracle semantics;
- explicit SK901 suppression on the first or closing line of a multiline simple statement suppresses SK901 only inside that statement, marks SK900 usage correctly, and never propagates through compound statement bodies;
- `sleep(0.2)`, `range(40)` and anonymous buffer sizes remain SK901-owned;
- SK510 still rejects `contextlib.suppress`;
- hot-path `try`/`except` still triggers SK506;
- recognized cleanup/lifecycle boundaries no longer require mass SK506 suppressions;
- SK900 should expose stale SK506 suppressions after the semantic change;
- no new diagnostics from unrelated rule families versus the accepted 0.1.49 baseline;
- formatter must not create a dangling `platform` reference when one `from sys import platform` binding is used both in a runtime branch and in a decorator expression;
- the mixed decorator/runtime repro must remain importable/executable after `sklint format`;
- additional SK504 regression coverage should exercise defaults, annotations, comprehensions and shadowing as fail-closed no-fix contexts.
- SK608 result for a class method is invariant under unrelated preceding top-level functions/classes/constants;
- project-aware multiple-inheritance/re-export cases emit at most one exact SK619 per semantic violation;
- module-level `__getattr__` may raise `AttributeError` without SK507, while `RuntimeError` there and `AttributeError` in ordinary functions remain SK507;
- SK505 ignores deferred global lookup from function/method/async/lambda bodies but still reports eager module expressions, defaults, decorators and class bases;

The previous corpus estimate `SK901 2345 -> about 824` is only an upper-bound estimate. It is not an acceptance result; exact added/removed diagnostics must be measured.
