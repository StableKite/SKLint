# SKLint 0.1.41 — hardening SK801

## Подтверждённый дефект

В SKLint 0.1.40 правило SK801 анализировало только одну физическую строку после присваивания. Дополнительные использования переменной в продолжении многострочного statement не учитывались, а содержимое f-string было замаскировано. Поэтому safe-fix мог удалить присваивание и заменить только первое использование, оставляя последующие обращения к неопределённому имени.

## Исправление

- граница следующего выражения определяется как полный логический statement, включая скобочные и backslash-продолжения;
- перед выдачей safe-fix имя проверяется во всём statement;
- учитываются дополнительные упоминания в исходном тексте, включая f-string;
- одновременно проверяется маскированный код, чтобы единственная цель замены гарантированно находилась в коде, а не в строке или комментарии;
- при нескольких или неоднозначных использованиях SK801 не выдаёт safe-fix и не удаляет промежуточную переменную;
- сохранён положительный автофикс для многострочного statement с ровно одним использованием.

Добавлены три regression-теста:

1. два использования, одно из которых находится внутри f-string;
2. несколько использований в многострочном вызове;
3. одно использование в многострочном вызове, которое по-прежнему безопасно сворачивается.

```python
    reliability=runtime.reliability

```
